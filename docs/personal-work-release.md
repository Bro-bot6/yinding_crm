# 我的客资与我的日历（2026-09-07）

## 使用变化

- 原“跟进任务”入口改为“我的客资”，保留原有 `#/followups` 路由。
- 列表单位为实际项目，按登录员工的商务/技术岗位和实际负责人判断归属。双岗位同项目只显示一次；未指定项目负责人且启用继承时沿用客户负责人。管理员可选择员工，默认查看自己。
- 可按等级、来源、省、市、阶段及名称/联系方式搜索，支持优先级、最近真实跟进时间排序及进行中/已完成切换。编辑资料时间不作为跟进时间。
- 原“明日安排”改为“我的日历”，保留 `#/plans` 路由。支持月、周、日程视图，任意日期、全天或定时事项、改期、完成、取消和确认删除。
- 日历仅本人可通过日历接口访问，关联客户/项目不会让其他负责人获得该日程。
- 提醒默认关闭，开启后仅在网站打开时显示站内提示，使用北京时间；全天事项按09:00计算。不提供系统推送、短信、微信或第三方日历同步。
- 任务完成不再改变正式项目阶段；项目保存不再自动生成阶段任务、截止时间或自动完成旧任务。正式阶段修改需要前端确认。
- 客户描述可展开/收起；新建、批量新增和修改名称/联系方式前检查疑似重复。用户可取消或选择仍然保存，不自动合并。

## 历史数据

迁移 `0030_personal_calendar` 只为原 `TomorrowItem` 增加字段。原ID、所属账号、日期、内容、完成状态、完成时间均保留。旧事项没有时间和类别记录，因此默认显示为全天个人事项，不猜测客户/项目关联，也不自动开启提醒。

原自动建议并不是个人事项，不复制为日历记录。原 `FollowUpTask` 仍保留供历史查看和维护；本次不删除客户、项目、任务或进度记录。

## 验证方式

- 后端：`manage.py test --noinput`，使用独立测试数据库。
- 前端：`node --test frontend/tests/*.test.cjs`。
- 可选本机隔离界面验证：先执行 `python scripts/personal_qa.py --prepare`，再执行 `python scripts/personal_qa.py`，只在127.0.0.1:8001提供服务。数据固定写入已忽略的 `private-qa-personal` 目录，不连接正式数据库。
- 正式服务启动入口会在迁移前备份数据库，再执行迁移与静态资源收集。前端脚本、样式采用统一版本 `20260907-1`。
